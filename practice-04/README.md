## Организация кода

- `task-service.js` — модель и операции над задачами без DOM и `localStorage`; результаты `{ ok, tasks }` или `{ ok: false, error }`; входной массив не меняется. `updateTask` проверяет поля через `createTask`, но его `completed: false` не используется: настоящий статус сохраняется через spread.
- `form-validation.js` — чистая `validateTaskDraft(draft, tasks, editingId)`: нормализует и проверяет id, title, priority, в режиме редактирования берёт `editingId`, возвращает все независимые ошибки сразу. DOM не трогает.
- `task-storage.js` — граница `localStorage`: оболочка `{ version, tasks }`, `JSON.stringify/parse`, проверка схемы (`isValidTaskList`), перехват исключений. Функции получают `storage` аргументом, поэтому их можно проверить на объекте-имитации без браузера и видна внешняя зависимость.
- `task-selectors.js` — видимая выборка по фильтру; `task-view.js` — создание DOM и отрисовка (через `textContent`, без `innerHTML`).
- `main.js` — состояние (`currentTasks`, `currentFilter`, `editingId`), события (`submit`, делегирование на списке и фильтрах, кнопка сброса), координация сервиса, хранилища и отрисовки.

Данные из JSON проверяются до использования, потому что успешный `JSON.parse` подтверждает только синтаксис: там может оказаться число, другая версия схемы, повторяющиеся id или задачи с неверными полями. Такая запись отклоняется целиком, приложение берёт копию исходного набора. `renderApp` не обращается к хранилищу; сохраняют только успешные add / update / toggle / delete.

## Отладка и клавиатура

Точка останова в `src/main.js`, строка 195 (`const checked = validateTaskDraft(draft, currentTasks, editingId);`). Сценарий: добавление `id = 20`, название «Изучить localStorage», приоритет «Средний». Значения прочитаны в DevTools (Sources → Scope → Local), после остановки и после выполнения строки клавишей F10.

Ошибочный сценарий — повторный id: черновик `{ id: "4", title: "Дубликат", priority: "low" }` даёт `{ ok: false, errors: { id: "Задача с id 4 уже существует" } }`; выполнение уходит в ветку `if (!checked.ok)` и завершается `return` до сервиса и до `saveTasks`, JSON в storage не меняется.

После ошибки в названии фокус переходит в поле названия.

## Вывод

Реализованы форма создания и редактирования (одна форма, режим определяется `editingId`), чистая прикладная валидация, функция `updateTask` и модуль хранения с проверкой схемы и перехватом исключений. Все проверки пройдены: сервис 35/35, новые модули 27/27, браузер 23/23. По ходу работы заметил, что после отказа в форме прежнее сообщение об успехе оставалось на экране; теперь оно снимается при ошибке.

Три уровня проверки решают разные задачи. Нативная проверка HTML (`required`, `min`, `step`, `maxlength`) блокирует очевидно неверный ввод до `submit`, но не знает предметных правил и пропускает пробелы. Прикладная валидация (`trim`, уникальность id, приоритет, наличие редактируемой задачи) выдаёт понятные ошибки полей. Проверка данных после чтения из хранилища нужна потому, что успешный `JSON.parse` подтверждает только синтаксис: версия и схема проверяются отдельно, а сломанная запись заменяется исходным набором. `localStorage` — учебное хранилище одного браузера, не защита данных и не серверная база.
