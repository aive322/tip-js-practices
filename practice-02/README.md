## 4. Модель данных и функции

**Модель задачи:** `{ id, title, completed, priority }`.

| Поле | Правило |
|---|---|
| `id` | Положительное безопасное целое число, тип `number`, без приведения типов. Уникально в пределах списка. |
| `title` | Строка. После `trim()` длина от 1 до 100. Хранится очищенная строка, внутренние пробелы сохраняются. |
| `completed` | Логическое значение. Новая задача всегда создаётся с `false`. |
| `priority` | Строго `"low"`, `"medium"` или `"high"`. По умолчанию `"medium"`. |

**Файлы:**
- `src/data.js` хранит только данные: общий набор `demoTasks` и набор варианта `variantTasks`.
- `src/task-service.js` содержит девять прикладных функций. В нём нет `console.log` и глобального списка, каждая функция работает только с переданными аргументами.
- `src/main.js` импортирует данные и функции, показывает сценарии и выводит результаты. Вычисления он не дублирует.
- `checks.js` (готовый) и `own-checks.js` (мои) проверяют функции без вывода в интерфейс.

**Результаты функций:**

| Функция | При успехе | При ошибке |
|---|---|---|
| `createTask` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById` | найденный объект | `undefined`, если задачи нет |
| `getPendingTasks` | новый массив невыполненных (может быть пустым) | ошибки нет |
| `getTaskTitles` | новый массив названий | ошибки нет |
| `getTaskStats` | `{ total, completed, pending, progress }` | ошибки нет |
| `addTask`, `setTaskCompleted`, `renameTask`, `removeTask` | `{ ok: true, tasks: новыйМассив }` | `{ ok: false, error }` |

Ожидаемые ошибки (неверный тип или диапазон, повторяющийся `id`, отсутствующая задача) возвращаются как данные, а не обрывают программу исключением.

**Почему id не равен индексу:** индекс показывает текущее место в массиве и меняется при удалении соседних записей. `id` идентифицирует запись и после удаления остальных не меняется. Поэтому поиск выполняется через `find` по полю `id`, а не обращением `tasks[id]`. Например, задача с `id = 4` лежит по индексу 1.

**Почему getTaskStats возвращает число, а не строку с процентом:** число можно использовать дальше в расчётах и сравнениях. Метод `toFixed()` возвращает строку, поэтому округление выполняется только при выводе в `main.js`. Предварительное округление искажало бы значение: например, для трёх задач при одной выполненной получается `33.3333...`, а не `33.3`.

**Какие объекты копируются при изменении задачи:** создаются новый массив и новый объект выбранной задачи (`{ ...task, completed }` или `{ ...task, title }`). Остальные объекты в новом массиве используются повторно, но их свойства не меняются. Исходный массив и исходные объекты не изменяются.

## 9. Вывод

В ПР1 вычисления выполнялись над отдельными переменными, а в ПР2 задача стала объектом, список задач массивом, а операции над ним функциями. Это позволило отделить логику (`task-service.js`) от данных (`data.js`) и вывода (`main.js`), а значит, одну и ту же логику можно будет использовать и в интерфейсе.

Возвращаемые значения используются во всех функциях: результат операции возвращается, а вывод остаётся за `main.js`. Ожидаемые ошибки возвращаются объектом `{ ok: false, error }`, поэтому программа при них не падает. Неизменность данных проверена снимками (`JSON.stringify` в сценариях и глубокая копия в `own-checks.js`) до и после операций, а не только сравнением ссылок на массив.

Самой показательной оказалась ошибка из эксперимента 2: стрелочная функция с `{ }` без `return` не вызывает ни исключения, ни предупреждения, она тихо возвращает `undefined`. Вторая важная находка: `[...products]` копирует массив, но не объекты внутри него, поэтому при изменении записи нужно создавать и новый объект задачи.
